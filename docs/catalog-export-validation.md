# اعتبارسنجی خروجی رسمی کاتالوگ Website

**وضعیت:** بررسی فقط‌خواندنی — هیچ فایل Website، CSV، Excel، دیتابیس، Migration، Seed یا کدی تغییر نکرده است.  
**قرارداد مبنا:** `docs/catalog-import-contract.md` (قفل‌شده)  
**کاتالوگ محلی `catalog.xlsx`:** در این بررسی برای Import استفاده نشده است.  
**تاریخ:** ۱۹ اوت ۲۰۲۶

---

## نتیجه کوتاه

خروجی رسمی کاتالوگ محصول پیدا شد.

فایل اصلی قابل بررسی روی دیسک:

`/Users/ehsanmohammadi/website/product-list-by-menu.csv`

این فایل را اسکریپت خواندنی `scripts/export-product-brand-list.mjs` از دیتابیس محلی Website می‌سازد. ستون کد همان `sku` است و در هدر «کد یکتا محصول» آمده است.

**تبدیل مستقیم و کامل به قرارداد Import ممکن نیست.**  
هویت کالا (`sku` → `product_code`، نام، گروه، دسته) برای اکثر ردیف‌ها قابل نگاشت است، اما ساختار `brandIds` / `brandOffers`، شناسه پایدار برند (`slug` / `_id`)، و مشخصات فنی در این CSV نیستند. شش `sku` تکراری با نام متفاوت هم با قاعده رد تضاد قرارداد برخورد می‌کنند.

هیچ `sku` یا `product_code` جدیدی ساخته نشد.

## ۷) ساختار `brandIds`

در خروجی CSV **وجود ندارد**.

تگ‌ها فقط نام فارسی پشت‌سرهم در ستون‌های «برند ۱…۳۵» هستند. شناسه Mongo، `slug`، و آرایه `brandIds` در فایل نیست.

نمونه میلگرد آجدار: هر ۱۶ کالا ۳۵ نام برند یکسان دارند (شروع با ذوب آهن اصفهان، فولاد زاگرس، فولاد کوثر اهواز، …). این با مدل Website «یک محصول پایه + آرایه تگ» سازگار است، اما فقط لایه نمایش است نه ساختار داده.

## ۸) ساختار `brandOffers`

در خروجی CSV **وجود ندارد**.

ستون قیمت به‌ازای برند، `isActive`، و `brandId` نیست. API `.../brand-offers/csv` این را برای **یک** محصول می‌دهد نه برای کل کاتالوگ؛ نمونه کامل روی دیسک نبود.

- گروه خالی: ۰
- دسته خالی: ۰

تکراری/مبهم:

- برندهای هم‌نام در چند گروه فقط با نام نمایشی آمده‌اند و `slug` ندارند؛ از جمله «یزد» در تیرآهن و نبشی و ناودانی، «اهواز» در تیرآهن و لوله. قرارداد این‌ها را بدون `website_brand_id` مبهم می‌داند.

`Brand-lule.csv` جداگانه slug برند لوله دارد، ولی خروجی کاتالوگ محصول آن را وصل نکرده است. این بررسی آن فایل را جایگزین کاتالوگ نکرد.

## ۱۱) امکان تبدیل مستقیم به قرارداد Import

| بخش قرارداد | با این CSV |
| --- | --- |
| `sku` → `product_code` عیناً | بله، برای ۱٬۲۵۵ کد یکتا |
| نام پایه | بله |
| گروه و دسته نمایشی | نسبی؛ گروه CSV با هفت گروه قرارداد یکی‌به‌یکی نیست |
| محصول بدون برند | بله؛ ۴۵۱ ردیف قابل پذیرش بدون تگ |
| `brandIds` → `product_brand_tags` | خیر — ساختار نیست |
| `brandOffers` | خیر — ساختار نیست |
| `website_brand_id` الزامی تگ | خیر — فقط نام نمایشی |
| مشخصات فنی اختیاری | غایب؛ مانع هویت نیست |
| رد تکراری داخل فایل | باید ۶ کد متضاد را کامل رد کند |
| idempotent بر `product_code` | پس از رد تکراری‌ها، از نظر کلید کالا ممکن است |
| عدم ساخت کالا از متن قیمت | رعایت می‌شود اگر فقط همین خروجی منبع باشد |

جمع: **تبدیل جزئی هویت کالا ممکن است؛ تبدیل کامل تگ برند و کلید `product_code + brand_id` از روی همین فایل ممکن نیست.**

## ۱۲) مغایرت با قرارداد

1. قرارداد تگ را از `brandIds` / `brandOffers` و هویت برند Website می‌خواهد؛ CSV فقط نام تخت دارد.
2. قرارداد `website_brand_id` (`slug` یا `_id`) را برای ساخت تگ اجباری می‌داند؛ در این خروجی نیست.
3. شش `sku` تکراری با نام متفاوت خلاف یکتایی ورودی است.
4. گروه «نبشی و ناودانی» در برابر دو گروه جدا در طرح دیتابیس.
5. همه پروفیل‌ها یک دسته دارند؛ ریزدسته Website در این export نیست.
6. API ادمین CSV اگر بعداً استفاده شود ستون قیمت دارد؛ قرارداد ذخیره قیمت Website در Import هویت را منع کرده است.
7. اسکریپت export در کد، `sku` خالی را با `_id` پر می‌کند؛ این با ممنوعیت ساخت کد جدید هم‌خوان نیست. در فایل فعلی موردی دیده نشد، ولی اگر بعداً رخ دهد باید `rejected_incomplete` شود نه پذیرش `_id` به‌عنوان `product_code`.

## حکم برای مرحله بعد

خروجی رسمی پیدا شد و برای شمارش کالا و `sku` قابل استناد است.

برای اجرای Import مطابق قرارداد قفل‌شده، این CSV به‌تنهایی کافی نیست مگر:

- شش `sku` متضاد از منبع Website رفع شوند، و
- تگ برند با شناسه پایدار (حداقل `slug`) در خروجی کاتالوگ بیاید، یا خروجی جدا و رسمی brand-offers برای همه کالاها ارائه شود.

تا آن زمان Seed/Import اجرا نمی‌شود. `catalog.xlsx` منبع هویت نیست و در این بررسی استفاده نشد.
