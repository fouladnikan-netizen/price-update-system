# قرارداد مفهومی هویت محصول و قیمت

**وضعیت:** سند طراحی مفهومی — بدون تغییر فایل داده، دیتابیس، Seed یا کد.  
**مبنای تأییدشده:** `docs/catalog-review.md` و `docs/brand-catalog-review.md`  
**تاریخ:** ۱۹ اوت ۲۰۲۶

این سند هویت موجودیت‌ها را قفل می‌کند. تا دریافت `product_code` و `brand_id` از Website، هیچ کد محصولی حدس زده یا تولید نمی‌شود.

---

## ۱) اصول قطعی

1. محصول Website **محصول پایه** است. هویت آن فقط `product_code` است.
2. برند **محصول مستقل نیست**. برند تگ / ارتباط مجاز (`Brand Association`) روی محصول یا دسته است.
3. برای کالای برنددار، شناسه محل قیمت برابر است با `product_code + brand_id`.
4. برای کالای بدون برند، شناسه محل قیمت برابر است با `product_code`.
5. ورود برند جدید **هرگز** `product_code` جدید نمی‌سازد.
6. سامانه `product_code` را حدس نمی‌زند، از نام کالا نمی‌سازد، و از ترکیب گرید/سایز/برند تولید نمی‌کند.
7. برندهای هم‌نام بر اساس **گروه و دسته** از هم جدا می‌مانند تا وقتی Website آن‌ها را یکی اعلام کند.
8. نبود فهرست برند برای بعضی گروه‌ها یا دسته‌ها **خطا نیست**. آن کالاها بدون‌برند قیمت می‌گیرند.
9. نام کالا فقط برای نمایش و پیشنهاد تطبیق است. معیار ثبت، بررسی نهایی و انتشار نیست.
10. قیمت کارخانه و قیمت انبار دو نوع قیمت جدا روی همان محل قیمت‌اند، نه دو محصول.

نمونه منسوخ: کدی مانند `REB-A3-14-ESF` که برند را داخل `product_code` می‌گذارد با این قرارداد سازگار نیست و استفاده نمی‌شود.

---

## ۲) موجودیت‌ها

### ۲.۱ محصول پایه (`Product`)

کالای فنی بدون کارخانه.

| فیلد مفهومی | نقش |
| --- | --- |
| `product_code` | هویت پایدار و مشترک با Website؛ منبع فقط Website |
| گروه اصلی | میلگرد، تیرآهن، ورق، نبشی، ناودانی، پروفیل، لوله |
| دسته | برچسب ریزتر داخل گروه |
| نام استاندارد | نام نمایشی پایه؛ مثلاً «نبشی ۴» |
| مشخصات فنی | گرید، سایز، ضخامت، طول، رده لوله، شکل عرضه |
| وضعیت | فعال / غیرفعال |

قواعد:

- یک `product_code` = یک محصول پایه.
- محصول پایه برند ندارد.
- اگر Website برای «نبشی ۴» یک کد دارد، سامانه همان را نگه می‌دارد؛ برای شکفته یا بناب کد دوم ساخته نمی‌شود.

### ۲.۲ برند (`Brand`)

کارخانه، تولیدکننده یا تگ بازاری تأییدشده.

| فیلد مفهومی | نقش |
| --- | --- |
| `brand_id` | هویت پایدار برند؛ منبع ترجیحی Website |
| نام نمایشی | نام کوتاه سایت؛ مثلاً «شکفته» |
| نام حقوقی | نام ثبتی کارخانه؛ برای ابهام‌زدایی انسان |
| نام‌های جایگزین | املا و نام بازاری دیگر برای تطبیق، نه برای هویت |
| دامنه مجاز | گروه و دسته‌هایی که این تگ در آن‌ها معتبر است |

قواعد:

- برند به‌تنهایی قیمت ندارد.
- برند به‌تنهایی در Website محصول نمی‌شود.
- نبود `brand_id` محلی مجوز ساخت `product_code` نیست.

### ۲.۳ ارتباط برند (`ProductBrandTag` / Brand Association)

مجوز اتصال یک تگ برند به یک محصول پایه، یا به همه محصولات یک دسته.

| فیلد مفهومی | نقش |
| --- | --- |
| `product_code` یا دامنه دسته | هدف ارتباط |
| `brand_id` | تگ مجاز |
| گروه / دسته | محدوده اعتبار تگ |

این ارتباط هویت قیمت نیست؛ فقط می‌گوید «این برند روی این کالا مجاز است».

### ۲.۴ محل قیمت (`Price Slot`)

چیزی که روزانه برای آن قیمت کارخانه و قیمت انبار نگه داشته می‌شود.

| نوع کالا | شناسه محل قیمت | مثال نمایش |
| --- | --- | --- |
| برنددار | `product_code + brand_id` | نبشی ۴ شکفته |
| بدون برند | `product_code` | پروفیل ۲۰×۲۰ ضخامت ۲ میل |

`brand_id` تهی برای کالای بدون‌برند مقدار معتبر است، نه داده گم‌شده.

### ۲.۵ مشاهده قیمت (`Price Observation`)

یک قیمت استخراج‌شده از یک منبع، قبل از انتخاب قیمت نهایی روز.

وابسته است به محل قیمت، به‌اضافه نوع قیمت، تاریخ، منبع و داده خام.

### ۲.۶ قیمت نهایی روزانه (`Daily Price`)

قیمت تأییدشده همان روز برای همان محل قیمت و همان نوع قیمت (کارخانه یا انبار).

روز بدون قیمت = داده غایب / `null`، هرگز صفر.

---

## ۳) شناسه‌ها

### ۳.۱ هویت محصول پایه

```text
ProductKey = product_code
```

فقط از Website می‌آید. خالی بودن آن یعنی محصول هنوز قابل Seed، تطبیق قطعی و انتشار نیست.

### ۳.۲ هویت برند در محدوده گروه و دسته

نام کوتاه به‌تنهایی هویت نیست.

تا وقتی `brand_id` Website موجود باشد، همان کافی است.

تا آن زمان، کلید موقت محلی فقط برای جلوگیری از ادغام غلط است:

```text
LocalBrandDisambiguationKey = group + category + display_name
```

نباید به‌عنوان کد انتشار یا جایگزین `product_code` ذخیره شود.

مثال تفکیک هم‌نام:

| گروه | دسته | نام نمایشی | هویت |
| --- | --- | --- | --- |
| تیرآهن | تیرآهن | یزد | جدا از نبشی یزد |
| نبشی | نبشی | یزد | جدا از تیرآهن یزد |
| ورق | ورق گالوانیزه | کاشان | جدا از کویر کاشان |
| میلگرد | میلگرد | کویر کاشان | جدا از کاشان ورق |

ادغام دو تگ فقط با اعلام صریح Website مجاز است. تشابه نام حقوقی یا نام بازاری برای ادغام کافی نیست.

کارخانه واحد روی چند دسته (مثلاً فولاد مبارکه روی چند نوع ورق) می‌تواند یک `brand_id` داشته باشد، اگر Website همان تگ را مشترک بداند. این اشتراک حدس زده نمی‌شود.

### ۳.۳ شناسه محل قیمت

```text
اگر برند دارد:
  PriceSlotKey = product_code + brand_id

اگر برند ندارد:
  PriceSlotKey = product_code
```

برند جدید فقط `PriceSlotKey` جدید می‌سازد، نه محصول جدید.

### ۳.۴ شناسه مشاهده و قیمت روزانه

این‌ها روی محل قیمت سوار می‌شوند و جایگزین آن نیستند:

```text
ObservationKey ⊇ PriceSlotKey + price_type + observed_at + source_id + raw_item_id

DailyPriceKey  = PriceSlotKey + price_type + price_date
```

`price_type` فقط `factory` یا `warehouse` است.

## ۴) قواعد نمایش

| سطح | الگو | مثال |
| --- | --- | --- |
| محصول پایه | نام استاندارد | نبشی ۴ |
| کالای برنددار | نام استاندارد + نام برند | نبشی ۴ شکفته |
| کالای بدون برند | نام استاندارد | پروفیل ۲۰×۲۰ |
| تب UI دسته | «همه برندها» + یک تب برای هر تگ مجاز همان دسته | همه برندها، شکفته، بناب |
| دسته بدون فهرست برند | فقط نمای محصول پایه؛ نبود تب برند خطا نیست | پروفیل |

برند در عنوان صفحه محصول پایه تکرار نمی‌شود. برند فقط روی ردیف قیمت و تب فیلتر دیده می‌شود.

---

## ۵) قواعد ورود، تطبیق و انتشار

### ۵.۱ ورود کاتالوگ

- ردیف کاتالوگ محلی، اگر `product_code` Website نداشته باشد، محصول قابل انتشار نیست.
- مشخصات فنی برای کمک به تطبیق انسان و پیشنهاد ماشینی است، نه برای ساخت کد.
- وزن تقریبی و جدول وزن تیرآهن هویت نیستند.

### ۵.۲ ورود برند

- فهرست برند هر گروه/دسته منبع تگ‌های مجاز همان محدوده است.
- گروه یا دسته‌ای که فهرست برند ندارد، کالای بدون‌برند محسوب می‌شود.
- تکمیل بعدی فهرست برند، محصولات موجود را تکثیر نمی‌کند؛ فقط ارتباط تگ اضافه می‌کند.

### ۵.۳ تطبیق منبع قیمت

ترتیب تصمیم:

1. اگر `product_code` معتبر Website مشخص نشد → ثبت به‌عنوان نامنطبق؛ انتشار ممنوع.
2. اگر کالا در دامنه برنددار است و برند منبع به `brand_id` مجاز همان گروه/دسته رسید → محل قیمت = `product_code + brand_id`.
3. اگر کالا در دامنه بدون‌برند است → محل قیمت = `product_code`.
4. اگر کالا برنددار است ولی برند منبع خالی یا نامعتبر است → مشاهده مشکوک / نیازمند بررسی؛ حدس برند ممنوع.
5. تطبیق قطعی با نام کالا به‌تنهایی ممنوع است.

دامنه برنددار یعنی برای آن گروه و دسته حداقل یک تگ برند تأییدشده وجود دارد. دامنه بدون‌برند یعنی فهرست تگ برای آن گروه/دسته خالی است و این وضعیت مجاز است.

### ۵.۴ انتشار به Website

حداقل داده انتشار:

| فیلد | کالای برنددار | کالای بدون برند |
| --- | --- | --- |
| `product_code` | الزامی؛ کد پایه Website | الزامی؛ کد پایه Website |
| `brand_id` | الزامی | ارسال نمی‌شود / تهی |
| نوع قیمت | الزامی | الزامی |
| مبلغ | الزامی؛ صفر به‌معنای نبود قیمت نیست | الزامی |
| تاریخ اعتبار | الزامی | الزامی |

اگر `product_code` در Website نباشد، انتشار متوقف می‌شود.  
اگر کالا برنددار باشد و `brand_id` نباشد، انتشار متوقف می‌شود.  
تکرار ارسال همان `DailyPriceKey` نباید قیمت را دوباره ثبت کند.

---

## ۶) آنچه هویت نیست

این‌ها ممکن است ذخیره شوند، اما کلید محصول یا محل قیمت نیستند:

- نام کالا، نام منبع، یا متن آگهی
- اسلاگ فارسی/انگلیسی ساخته‌شده در فایل محلی
- وزن شاخه، واحد نمایش، یا جدول وزن برند×سایز
- گرید، سایز، ضخامت، طول (مشخصه محصول پایه‌اند، نه جایگزین کد)
- نوع قیمت، منبع، یا کاربر تأییدکننده
- مقدار متنی `NULL` در کاتالوگ محلی

---

## ۷) حالت‌های مجاز و غیرمجاز

| وضعیت | حکم |
| --- | --- |
| محصول پایه Website با چند تگ برند | مجاز؛ چند محل قیمت روی یک `product_code` |
| محصول پایه بدون هیچ تگ برند | مجاز |
| برند بدون اتصال به محصول | مجاز به‌عنوان فهرست تگ؛ قیمت ندارد |
| ساخت محصول جدید فقط به‌خاطر برند جدید | غیرمجاز |
| تولید `product_code` از نام یا از برند | غیرمجاز |
| یکی‌کردن «یزد» تیرآهن و «یزد» نبشی فقط به‌خاطر نام | غیرمجاز |
| قیمت بدون برند برای دسته‌ای که تگ برند دارد | مشکوک؛ نیاز به بررسی انسان |
| قیمت بدون برند برای دسته‌ای که تگ برند ندارد | عادی |
| انتشار با حدس محصول از روی نام | غیرمجاز |
| روز بدون قیمت | `null` / غایب |

## ۸) پیامد برای داده فعلی (بدون اصلاح)

از گزارش‌های تأییدشده، فقط برای هم‌ترازی قرارداد:

- کاتالوگ محلی `product_code` ندارد؛ پس هنوز هیچ `ProductKey` قطعی در این مخزن نیست.
- فایل برند `brand_id` ندارد؛ پس `PriceSlotKey` برنددار هنوز قابل Seed نیست.
- میلگرد، تیرآهن، نبشی، ناودانی، مانیسمان و چند دسته ورق دامنه برنددار بالقوه دارند.
- پروفیل و بیشتر لوله‌ها فعلاً دامنه بدون‌برنداند؛ این شکاف داده است نه خطای مدل.
- تا آمدن کدهای Website، سامانه نباید کاتالوگ محلی را به‌عنوان هویت نهایی بارگذاری کند.

---

## ۹) کارهای خارج از این سند

این قرارداد انجام نمی‌دهد و هنوز اجرا نشده است:

- دریافت یا حدس `product_code` از Website
- ساخت برند، محصول، Seed، Migration یا کد
- اصلاح Excel کاتالوگ یا فایل Numbers برند
- تعیین اینکه کدام جفت تگ میلگرد (مثلاً صنعت بناب / شاهین بناب) در Website یکی هستند

پس از تأیید این قرارداد، مرحله بعد فقط می‌تواند مشخص کردن منبع رسمی `product_code` و `brand_id` از Website باشد.
