# گزارش بررسی کاتالوگ محصولات

**وضعیت:** بررسی فقط‌خواندنی — فایل Excel تغییر نکرده است.  
**مسیر فایل:** `data/products/catalog.xlsx`  
**حجم:** ۷۹٬۶۱۱ بایت  
**آخرین ویرایش فایل:** ۱۲ اوت ۲۰۲۶  
**تاریخ بررسی:** ۱۹ اوت ۲۰۲۶  
**CSV معادل:** `data/products/catalog.csv` وجود ندارد.

**نتیجه کلی:** ساختار فعلی کاتالوگ برای ورود به سامانه **مناسب نیست** و قبل از Seed دیتابیس نیاز به اصلاح و تأیید دارد. هیچ محصول، برند یا `product_code` جدیدی در این مرحله ایجاد نشده است.

## خلاصه وضعیت کاتالوگ

کاتالوگ یک فهرست فنی از کالاهاست، نه یک فهرست هویت‌دار قابل اتصال به Website.

| شاخص | مقدار |
| --- | --- |
| تعداد شیت | ۳ |
| شیت اصلی محصولات | `Sheet1` |
| ردیف داده در شیت اصلی | ۱٬۲۳۶ |
| ستون `product_code` | **وجود ندارد** |
| ستون برند در شیت محصولات | **وجود ندارد** |
| ستون گروه اصلی | **وجود ندارد** |
| دسته‌های یکتا | ۴۱ |
| برندهای داخل شیت محصولات | ۰ |
| برندهای جدول وزن تیرآهن | ۱۰ |
| پایلوت میلگرد (آجدار + ساده) | ۲۹ ردیف |

طبق `AGENTS.md` و بریف سامانه:

- هویت مشترک محصول `product_code` است.
- محصول بدون حدس از روی نام منتشر نمی‌شود.
- ساختار منطقی سامانه: گروه اصلی ← دسته ← محصول ← برند ← قیمت.

کاتالوگ فعلی فقط تا سطح «دسته + مشخصات فنی + نام کالا» پیش رفته است. برند روی محصول ثبت نشده و کد یکتا وجود ندارد. بنابراین Seed، تطبیق قیمت، و انتشار Website روی این فایل قابل اعتماد نیست.

پوشه‌های `apps/`، `packages/` و `database/` در حال حاضر خالی هستند. این گزارش تنها خروجی این مرحله است.

## ستون‌های شناسایی محصول

ستون‌های موجود که می‌توانند در شناسایی کالا نقش داشته باشند:

| فیلد | نقش فعلی | آیا هویت پایدار است؟ |
| --- | --- | --- |
| دسته | طبقه‌بندی | خیر؛ ۴۱ برچسب بدون کد و بدون گروه والد |
| نام کالا | برچسب نمایشی | خیر؛ تکراری، یک مورد خالی، گاهی با ستون ابعاد ناسازگار |
| نوع | ویژگی چندمعنا | خیر؛ نقش ستون بین دسته‌ها عوض می‌شود |
| ابعاد/طول | مشخصه فیزیکی | مکمل است، نه شناسه |
| سایز | مشخصه فیزیکی | فرمت ناهمگن |
| وزن تقریبی | مشخصه تخمینی | هویت نیست؛ گاهی `NULL` |
| واحد | واحد وزن/شاخه | هویت نیست |
| رده لوله | فقط مانیسمان | برای بقیه دسته‌ها significnt نیست |
| ضخامت | مشخصه فیزیکی | گاهی با `سایز` تکرار می‌شود |

ستون‌های لازم سامانه که در فایل نیستند:

- `product_code`
- گروه اصلی (`ProductGroup`)
- برند / تولیدکننده روی هر محصول
- نام‌های جایگزین
- وضعیت فعال/غیرفعال
- واحد قیمت هدف (مثلاً کیلوگرم) جدا از واحد وزن شاخه
- نگاشت به Website

طبق بریف، نمونه قرارداد انتشار این شکل است:

```json
{ "product_code": "REB-A3-14-ESF", ... }
```

این الگو نشان می‌دهد هویت محصول احتمالاً ترکیب گروه + گرید + سایز + برند است. کاتالوگ فعلی هیچ‌کدام از کد و برند را روی ردیف کالا ندارد.

**نتیجه:** با این ستون‌ها می‌توان کالا را برای انسان توصیف کرد، اما نمی‌توان آن را به‌صورت پایدار به قیمت، تطبیق، یا Website وصل کرد.

## وضعیت `product_code`

| شیت | ستون `product_code` | کد تکراری | کد خالی |
| --- | --- | ---: | ---: |
| `Sheet1` | ندارد | ۰ (کدی وجود ندارد) | ۱٬۲۳۶ (همه ردیف‌های داده) |

هیچ ستون معادل (`code`، `sku`، `id`، «کد»، «کد محصول») هم پیدا نشد.

پیامدها:

- Seed دیتابیس هویت یکتا برای محصول نمی‌سازد.
- تطبیق قیمت اگر بر نام تکیه کند، خلاف قانون پروژه است.
- انتشار به Website بدون کد مشترک باید متوقف شود.
- تولید خودکار کد در این مرحله انجام نشده و نباید انجام شود، مگر پس از تأیید صریح و هم‌ترازی با Website.

نزدیک‌ترین کلید عملیاتی فعلی ترکیب همه ستون‌های فنی است. با این کلید، ردیف کاملاً تکراری در `Sheet1` وجود ندارد. این فقط یکتایی داخل فایل است، نه هویت سامانه.

## وضعیت برندها

### داخل شیت محصولات

ستون برند وجود ندارد. هیچ ردیف محصول به کارخانه یا برند وصل نشده است.

برای پایلوت میلگرد این شکاف جدی است: صفحه دسته باید تب «همه برندها» و تب هر برند را نشان بدهد، در حالی که ۲۹ ردیف میلگرد فقط گرید و سایز دارند.

### برندهای قابل مشاهده در همین فایل Excel

فقط در شیت وزن تیرآهن، ۱۰ برند آمده است. این فهرست را نمی‌توان برند کل کاتالوگ دانست؛ فقط برای وزن IPE است.

### فهرست‌های باقیمانده در Data Validation

در ستون C چند لیست قدیمی مانده که با داده فعلی هم‌خوان نیست:

| محدوده | مقادیر لیست | داده فعلی همان محدوده |

| `C420:C473` | لوله مانیسمان وارداتی، کاوه، ابهر، پاسارگارد، اهواز | `A 105 Gr.B` |

### فایل جانبی خارج از Excel

در `data/brands/Brand.numbers` یک فایل Numbers جدا هست. طبق دستور این مرحله، آن فایل منبع ایجاد برند نیست و در Seed استفاده نشده است. قبل از ورود برندها باید مشخص شود منبع رسمی برندها کاتالوگ Website است، همین Excel، یا فایل Numbers.

### ابهام معماری برند

بریف می‌گوید محصول فیلد برند دارد و نمونه کد `REB-A3-14-ESF` برند را داخل `product_code` می‌گذارد. باید قبل از توسعه تصمیم گرفته شود:

1. هر ردیف کاتالوگ یک کالا بدون برند است و برند فقط روی مشاهده قیمت می‌آید؛ یا
2. هر ترکیب کالا × برند یک `product_code` جدا است.

گزینه ۲ با قرارداد Website هم‌خوان‌تر است، اما کاتالوگ فعلی داده لازم برای آن را ندارد.

- نام دسته `پروفیل‌ چهارچوب` شامل نیم‌فاصله (`U+200C`) است و با بقیه پروفیل‌ها یکدست نیست.
- برای تیرآهن، بریف نمونه را برندها گرفته (ذوب‌آهن، فایکو). در فایل، دسته همان شکل پروفیل است (IPE / HEA / HEB) و برند جدا نشده.

### وضعیت پایلوت میلگرد

| مورد | مقدار |
| --- | --- |
| میلگرد آجدار | ۱۶ ردیف |
| میلگرد ساده | ۱۳ ردیف |
| برند | ندارد |
| `product_code` | ندارد |
| طول آجدار | شاخه ۱۲ متری |
| طول ساده | شاخه ۶ متری |

وزن‌های میلگرد تقریبی به‌نظر می‌رسند (مثلاً A3 قطر ۸ = ۴.۵ کیلوگرم در ۱۲ متر، در حالی که وزن اسمی شاخه حدود ۴.۷۴ است). برای نمایش وزن تقریبی قابل قبول است، اما نباید مبنای محاسبه قیمت قرار گیرد.

## ایرادها و ابهام‌های داده

### مسدودکننده ورود به سامانه

1. **نبود `product_code` در تمام ردیف‌ها.** بدون این فیلد Seed و انتشار مجاز نیست.
2. **نبود برند روی محصول.** UI دسته/تب برند و مدل `Product` بریف قابل پیاده‌سازی روی این داده نیست.
3. **نبود گروه اصلی.** ۴۱ دسته باید به ۷ گروه وصل شوند، اما این رابطه در فایل نیست.
4. **مشخص نبودن منبع رسمی هویت.** Website، همین Excel، یا فایل Numbers برند؟

### کیفیت و یکدستی داده

5. مقدار متنی `NULL` به‌جای سلول خالی: نوع ۵۴۵، رده لوله ۱٬۱۸۲، ضخامت ۹۹، وزن ۱۲۴.
6. ستون `نوع` چندمعنا است و برای schema پایدار مناسب نیست.
7. فرمت `سایز` ناهمگن است: عدد خام، `8 میل`، `20*20`، `10×10`، `1/2 اینچ`، `1¼ اینچ`، `1/2 1 اینچ`، فاصله ابتدا/انتها در ۱۷ ردیف.
8. واحد تیرآهن IPE برابر `شاخه` است؛ بقیه کالاها `کیلوگرم`. وزن همان ردیف‌ها در عمل کیلوگرم هر شاخه ۱۲ متری است.
9. یک نام کالا خالی است: ردیف ۷۳۷، ورق سیاه، نوع رول، سایز `2 میل`.
10. ۳۹ نام تکراری (هر کدام دقیقاً دو ردیف). ردیف کامل تکراری نیست؛ تفاوت معمولاً در `نوع` است (ST12/ST14، ورق مبارکه/گیلان). تطبیق با نام کالا این ردیف‌ها را قاطی می‌کند.
11. `ورق A283` و `ورقA283` دو دسته جدا برای یک خانواده.
12. در ۳۹ ردیف ورق ST52 / A516 / آتشخوار، ابعاد داخل نام با ستون `ابعاد/طول` جابه‌جا شده (`2000*12000` در نام و `2000*6000` در ستون، و برعکس).
13. در ۵ ردیف پروفیل چهارچوب با ضخامت ۲.۵، ستون `سایز` هنوز `2 میل` است.
14. مقدار سرگردان `۱۸۹٫۱۹` در `L559`.
15. برای نبشی، `نوع` سطح مقطع است (`40*40`) و `سایز` عدد کوتاه (`4`). نقش ستون‌ها عوض شده.
16. لوله گالوانیزه سایز ` 1/2 اینچ` (با فاصله ابتدایی) و `1/2 اینچ` را جدا دارد.
17. Data Validationهای قدیمی با داده فعلی تضاد دارند.
18. وزن هاش سبک سایز ۳۶ و ۴۰ هر دو ۱۳۴۴ ثبت شده؛ برای سایز ۴۰ مشکوک است.
19. شیت یادداشت صریحاً بخشی از وزن تیرآهن را تخمین نسبی نسبت به اصفهان می‌داند.

### چیزهایی که در این فایل مشکل تکرار کد نیستند

- ردیف کامل تکراری در `Sheet1` نیست.
- در جدول وزن تیرآهن، برند و اسلاگ تکراری نیستند.

## پیشنهاد اصلاحات (بدون اجرا)

این موارد فقط پیشنهاد است و اجرا نشده‌اند.

1. **تثبیت `product_code` از Website.** کد را از سامانه هدف بگیرید؛ در این پروژه کد جدید نسازید مگر Website همان کد را بپذیرد.
2. **یک شیت یا خروجی استاندارد محصول** با ستون‌های حداقل:
   - `product_code`
   - `group`
   - `category`
   - `standard_name`
   - `brand_code` / `brand_name` (اگر هویت محصول شامل برند است)
   - فیلدهای فنی جدا: `grade`، `size`، `thickness_mm`، `length`، `pipe_schedule`، `form`
   - `approx_weight`
   - `weight_unit`
   - `status`
3. **جدا کردن جدول برند** از کاتالوگ کالا. منبع برند را مشخص کنید (Website یا فهرست تأییدشده). فایل `Brand.numbers` را فقط پس از تأیید به‌عنوان منبع کمکی ببینید.
4. **جدا کردن جدول وزن** از هویت محصول. وزن برند×سایز موجودیت جدا است، نه جایگزین `product_code`.
5. **پاکسازی `NULL` متنی** به مقدار خالی واقعی / `null`.
6. **یکدست‌سازی دسته:** ادغام `ورق A283` و `ورقA283`؛ حذف نیم‌فاصله اضافه در `پروفیل‌ چهارچوب`.
7. **اصلاح ۳۹ ردیف جابه‌جایی ابعاد** در ورق ST52، A516 و آتشخوار.
8. **تکمیل نام خالی ردیف ۷۳۷.**
9. **یکدست‌سازی سایز:** عدد و واحد جدا؛ اینچ با یک فرمت؛ حذف فاصله اضافه.
10. **شکستن ستون `نوع`** به فیلدهای جدا به‌جای یک ستون چندمعنا.
11. **تصمیم واحد تیرآهن:** وزن کیلوگرم شاخه باشد، واحد نمایش `kg` بماند، و `شاخه` به‌عنوان واحد شمارش جدا ثبت شود.
12. **برای پایلوت میلگرد:** فقط دسته‌های میلگرد آجدار و ساده، به‌همراه برندهای تأییدشده Website، با `product_code` واقعی. تا آن زمان Seed نشود.
13. پس از تأیید، یک `catalog.csv` مشتق‌شده از کاتالوگ تأییدشده ساخته شود؛ از روی فایل فعلی به‌صورت خودکار محصول نسازید.

## تصمیم‌هایی که قبل از شروع توسعه باید تأیید شوند

لطفاً قبل از Seed، Migration، یا پیاده‌سازی منوی محصول به این سؤال‌ها پاسخ دهید.

1. **منبع حقیقت `product_code` کجاست؟** Website، کاتالوگ فعلی، یا فهرست جدا که هنوز داده نشده؟
2. **آیا اجازه داریم برای کالاهای بدون کد، کد جدید بسازیم؟** پیشنهاد این بررسی: خیر، تا همگام‌سازی با Website.
3. **آیا هویت محصول شامل برند است؟** یعنی `میلگرد A3 قطر ۱۴ ذوب‌آهن` یک محصول است، یا `میلگرد A3 قطر ۱۴` یک محصول و برند فقط روی قیمت؟
4. **منبع رسمی برندها کدام است؟** شیت وزن تیرآهن، `data/brands/Brand.numbers`، Website، یا فهرست دیگری که باید ارائه شود؟
5. **آیا پایلوت فقط میلگرد آجدار است، یا میلگرد ساده هم داخل پایلوت است؟** کلاف در فایل نیست؛ اضافه شود یا خارج از دامنه بماند؟
6. **نگاشت ۴۱ دسته به ۷ گروه بریف تأیید می‌شود؟** به‌ویژه دو دسته A283 و نام `پروفیل‌ چهارچوب`.
7. **وزن تقریبی کاتالوگ مرجع عملیاتی است یا فقط راهنما؟** شیت یادداشت بخشی را تخمینی دانسته است.
8. **واحد قیمت هدف برای میلگرد چیست؟** کیلوگرم، شاخه، یا هر دو به‌عنوان دو `price_type` جدا از کارخانه/انبار؟
9. **آیا جدول وزن تیرآهن برند×سایز باید موجودیت جدا در دیتابیس باشد، یا تا فاز تیرآهن کنار گذاشته شود؟**
10. **آیا ۳۹ نام تکراری باید در نام کالا گرید/منبع ورق را هم نشان بدهند، یا همان تکرار با فیلد `نوع` کافی است؟**
11. **فایل `Brand.numbers` در این مرحله بررسی شود یا بعد از تأیید کاتالوگ؟**
12. **پس از اصلاح کاتالوگ، آیا Seed فقط برای میلگرد پایلوت انجام شود و بقیه گروه‌ها بعداً وارد شوند؟**
